Architecture guide for index.html (Gantt chart view)

index.html is a single self-contained file: HTML + CSS + JavaScript, with no external dependencies. It renders a Gantt-style schedule from Asana project data.

2. High-Level Architecture

The page is built around a two-source data pipeline: embedded fallback data that ships with the file, and a live Asana API fetch that replaces it on load.

4. CSS Architecture

Layout System

The Gantt chart uses a 3-column CSS Grid for every row, defined by CSS custom properties on .gantt:

Activityvar(--act-col): 280px
Progressvar(--prog-col): 72px
Timeline Area1fr (flexible)

The same 3-column grid is used by:

  • .gantt-header-year — Year row: "Activity" label | "Progress" label | Year bands (2026, 2027)
  • .gantt-header-month — Month row: empty | empty | 12 month labels (Jul–Jun)
  • .gantt-row — Each task: name cell | progress % | timeline cell with positioned bar

Section header rows (.gantt-section) break out of the 3-column grid and span full width with grid-template-columns: 1fr.

Collapse/Expand Mechanism

Uses a pure-CSS adjacent sibling selector, no JS state:

/* Tasks hidden by default */
.section-tasks { max-height: 0; overflow: hidden; transition: max-height 0.3s; }

/* When previous sibling has .expanded, reveal tasks */
.gantt-section.expanded + .section-tasks { max-height: 2000px; }

Clicking a section header calls toggleSection(this), which toggles the .expanded class. The CSS + combinator does the rest.

6. Data Model

The TASKS[] array is the single source of truth for rendering. It has the same shape whether from embedded data or live Asana fetch:

TASKS = [
  {
    "section": "OTA Releases",       // Display name for section header
    "cat":     "cat-ota",            // Key into SECTION_COLORS for bar color
    "tasks": [
      {
        "name":            "Task title",
        "completed":       false,            // strikethrough + 100% progress
        "assignee":        "Winston Lee",    // shown in tooltip
        "resource_subtype": "milestone",     // "milestone" → diamond, else → bar
        "due":             "2026-09-30",    // end date (YYYY-MM-DD)
        "start":           "2026-07-01"     // optional start date
      }
    ]
  }
];

7. Render Pipeline

The render() function builds the entire chart in a single pass as a string, then sets innerHTML. Here's the generation order:

render()
1. Year header rowActivity | Progress | 2026 | 2027
2. Month header row(empty) | (empty) | Jul Aug Sep ... Jun
3. For each TASKS[] section:
3a. Section header rowClickable, shows collapse arrow + name + task count
3b. Section tasks wrapper<div class="section-tasks"> (collapsible)
3b-i. For each task: gantt-rowActivity cell + Progress cell + Timeline cell (grid lines + bar/diamond/tbd)
+ Legend HTML into #gantt-legend

The gridLinesHTML(tPct) helper is called once and reused for every timeline cell — it generates the 11 month-boundary lines and the today marker.

8. Bar Positioning Math

All bars and markers are positioned using percentage offsets within the .gr-timeline cell (which fills the 3rd grid column).

// Timeline range: Jul 1, 2026 → Jul 1, 2027 (12 months)
var TL_START = new Date(2026, 6, 1);
var TL_END   = new Date(2027, 6, 1);
var TL_MS    = TL_END - TL_START;  // total milliseconds in range

// Convert a date string to a left% value
function dateToPct(dateStr) {
  var d = new Date(dateStr + "T00:00:00");
  return clamp(0, ((d - TL_START) / TL_MS) * 100, 100);
}

// Bar: left = dateToPct(start), width = dateToPct(due) - dateToPct(start)
// Diamond: left = calc(dateToPct(due)% - 7px) to center the 14px marker

Note: Months don't have equal day counts, so the grid lines (at equal 1/12 intervals) don't perfectly match calendar month boundaries. The discrepancy is <2px at typical widths — visually negligible.

10. Data Sync: Two Paths

Path A: Live (browser-side)

Asana REST API Fetch
  • On page load, fetch() calls Asana with an inline PAT
  • Requests: name, completed, assignee.name, resource_subtype, due_on, start_on, memberships.section.name
  • parseAsanaData() groups tasks by section using SECTION_MAP
  • Overwrites global TASKS[], calls render() again
  • Sync badge updates to Live Data on success, Sync error on failure

Path B: Offline (sync.py)

sync.py — CLI Script
  • Reads PAT from ASANA_PAT env var or .asana_pat file
  • Fetches tasks from Asana API (server-side, with subtask expansion)
  • Regex-replaces the block between // @@TASKS_START@@ and // @@TASKS_END@@ in index.html
  • The updated embedded data is a fallback when the browser-side fetch fails (e.g., CORS, expired PAT, offline)

11. Embed Mode

Adding ?embed to the URL activates embed mode for iframe use inside dashboard.html:

  • Nav bar hidden
  • Page header hidden
  • Card border/radius removed (flush with iframe)
  • Posts { type: "cfx-resize", height } messages to parent window so the iframe auto-sizes
  • Uses MutationObserver on #gantt to detect content changes and re-notify height

13. Key Design Decisions

  • Single-file architecture — no build step, no bundler. Can be served from any static host or opened as a local file. Asana PAT is inline (accepted tradeoff for simplicity).
  • String-based rendering — render() builds HTML as a concatenated string, not DOM nodes. Fast for this data size (<50 tasks) and makes the full re-render pattern trivial.
  • CSS-only collapse — adjacent sibling selector avoids managing expand/collapse state in JS. The max-height transition provides animation.
  • Two-source data — embedded TASKS[] (always available, possibly stale) + live Asana fetch (fresh, but may fail). Render fires twice: once immediately with embedded data, once after API response.
  • No framework — vanilla JS + CSS. Zero dependencies keeps the page fast, portable, and easy to edit without tooling.
